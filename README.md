# MBTA Blue Line — Headway Stability Simulation

A data-driven discrete-event simulation (DES) of the MBTA Blue Line, built to study
**train bunching and headway stability**. The project pulls real-world MBTA performance
data, fits statistical distributions to observed travel/dwell/headway times, drives a
queue-based train simulation off those distributions, and then analyzes the simulated
output for spectral instability (bunching) using partial regression and the Nyquist
stability criterion.

## Pipeline overview

The project runs as a four-stage notebook pipeline. Run them in order — each stage
consumes artifacts produced by the previous one (artifacts live in [data/](data/) and
are git-ignored; see [Data](#data)).

| Stage | Notebook | What it does |
|---|---|---|
| 1 | [part1_extract_data.ipynb](part1_extract_data.ipynb) | Downloads daily subway on-time-performance parquet files from the [MBTA LAMP open data portal](https://performancedata.mbta.com), filters out rows missing `travel_time_seconds`/`dwell_time_seconds`, and concatenates them into a single master dataset (Oct 2024 + Oct 2025). |
| 2 | [part2_get_sim_components.ipynb](part2_get_sim_components.ipynb) | Exploratory data analysis to calibrate the simulation. Plots KDEs of travel time per origin→destination station pair, fits candidate distributions (Weibull, lognormal, gamma, Burr, inverse Gaussian, log-logistic, …) and selects the best fit by **AIC**. Builds the Blue Line network and saves it to `data/blue_network.pkl`. |
| 3 | [part3_run_sim.ipynb](part3_run_sim.ipynb) | The discrete-event simulation. A `Train`/`Sim` model dispatches trains over the calibrated network with a rush-hour parameter regime, replicated many times. Outputs station-level stats (`blue_station_stat.csv`), per-visit timetables (`blue_timetable.csv`), and headway data (`blue_headway.csv`). |
| 4 | [part4_post_sim_analysis.ipynb](part4_post_sim_analysis.ipynb) | Post-simulation analysis. Computes headway profiles and relative headway (deviation from ideal even spacing), runs **partial regression** (added-variable plots) to isolate leading→trailing train interactions, and applies the **Nyquist stability criterion** to residual headway signals to count spectrally unstable train pairs across replications. |

## Key concepts

- **Headway** — the time gap between two successive trains passing the same point. Even
  headways are good; growing/shrinking headways indicate *bunching*.
- **Target headway** — `2400 / n_trains` seconds, derived from the ~40-minute Blue Line
  round-trip cycle distributed evenly across trains.
- **Distribution fitting (AIC)** — travel/dwell times per station pair are modeled with
  the lowest-AIC parametric distribution so the simulation samples realistic times.
- **Nyquist stability** — partial-regression residual headway signals are checked against
  the Nyquist criterion to flag train pairs whose interaction is spectrally unstable.

## Data

Data files (`*.csv`, `*.parquet`, `*.pkl`) are **git-ignored** and not committed — they
are regenerated by running the pipeline. Notable artifacts:

- Raw MBTA LAMP performance data is fetched in stage 1 (no manual download needed).
- `data/blue_network.pkl` — the Blue Line network model (stage 2 output).
- `data/blue_station_stat.csv`, `data/blue_timetable.csv`, `data/blue_headway.csv` —
  simulation outputs (stage 3) consumed by the analysis (stage 4).
- [extract.txt](extract.txt) is an [Overpass](https://overpass-turbo.eu/) query used to
  pull MBTA commuter-rail line geometry and station nodes from OpenStreetMap.

## Getting started

1. Create a Python environment and install dependencies:

   ```bash
   pip install -r requirements.txt
   ```

   > `requirements.txt` is a full conda environment freeze (UTF-16 encoded). The core
   > stack is `pandas`, `numpy`, `scipy`, `scikit-learn`, `matplotlib`, `seaborn`,
   > `requests`, `fastparquet`, `tqdm`, and `jupyter`. A trimmed list is often enough.

2. Launch Jupyter and run the notebooks in order, `part1` → `part4`:

   ```bash
   jupyter lab
   ```

   Stage 1 requires internet access to reach the MBTA LAMP portal. Later stages read
   the artifacts written to [data/](data/) by earlier stages.
